# ImageMagick tools for Rex

The workflow host registers a semantic ImageMagick API as `tools.imagemagick`. The API is intended
for Rex programs generated by agents: workflows describe images, operations, and encodings rather
than executables, command-line arguments, or temporary files.

All `Image` values come from the shared `std.artifacts` module and refer to encoded content in the
workflow's content-addressable store:

```rex
import std.artifacts (Image);

Image { content = hash }
```

Every new image is imported into the store before it is returned. `SingleImage` represents one
encoded file, including animated or multipage formats. `MultipleImages` represents several encoded
files, normally produced with `SeparateFrames`.

ImageMagick is resolved as `magick` through `PATH`. ImageMagick scripts and `conjure` are not
exposed.

The API is strictly headless. It does not expose ImageMagick screen capture, display, animation
viewers, ambient font-family selection, or arbitrary installed pseudo-image sources. Interactive
and device-backed format names such as `X`, `WIN`, `SCREENSHOT`, `CLIPBOARD`, and `SCAN` are rejected
even when the installed ImageMagick build provides them.

## Main functions

| Function | Purpose | ImageMagick command |
|---|---|---|
| `transform` | Apply ordered operations to one source | `magick` |
| `generate` | Produce an image from a canvas, gradient, pattern, noise, or builtin | `magick` |
| `render` | Execute a typed multi-source image program | `magick` |
| `transform_many` | Batch-transform independent images | `magick mogrify` |
| `identify` | Return typed frame metadata | `magick identify` |
| `compare` | Measure image differences and optionally return a difference image | `magick compare` |
| `composite` | Combine a background, overlay, and optional mask | `magick composite` |
| `montage` | Create a contact sheet | `magick montage` |
| `extract_pixels` | Return a raw CAS-backed pixel buffer | `magick stream` |
| `version` | Return parsed version information | `magick -version` |
| `formats` | Return supported image format names | `magick -list format` |
| `capabilities` | Query an ImageMagick capability domain | `magick -list` |

## Sources

`StoredImage` reads CAS content and accepts an explicit frame selection plus read options. Other
source constructors generate images without a stored input:

- `Canvas`
- `LinearGradient`
- `RadialGradient`
- `Checkerboard`
- `NoiseImage`
- `BuiltinImage`

Read options cover density, colorspace, depth, page, size, alpha handling, background, profiles,
format hints, and coder-specific defines. A format hint is useful for headerless formats; ordinary
PNG, JPEG, WebP, GIF, and TIFF files can normally be detected from their bytes.

## Operations

Operations are applied in list order. The API covers these families:

- geometry, resizing, cropping, rotation, canvas extent, and liquid rescaling;
- blur, sharpen, noise, edge detection, deskew, and denoising;
- levels, contrast, thresholds, colorspaces, matrices, quantization, and white balance;
- alpha, channels, masks, CLUTs, and flood fill;
- convolution, morphology, FFT, connected components, and Hough lines;
- affine, perspective, polynomial, barrel, polar, and other distortions;
- drawing primitives, text, and styling;
- metadata, profiles, properties, coder defines, and color decision lists;
- sequence coalescing, optimization, appending, flattening, merging, and frame selection.

Geometry that agents commonly get wrong is represented with records and enums rather than strings.
`Grayscale` accepts an `IntensityMethod`, matching ImageMagick's `-grayscale` operator, while
`ConvertColorspace` accepts a `Colorspace`; these concepts are deliberately distinct.
Some ImageMagick-specific mini-languages remain nominal strings where their grammar is both large
and intrinsic to the operation, including kernels, threshold expressions, `fx` expressions,
format-specific defines, and advanced montage geometry.

Portable text drawing and montage should supply CAS-backed fonts (`DrawFont` and `MontageFont`). The
API does not expose ambient system font-family selection, and ImageMagick installations are not
required to provide a usable default font.

## Encoding

An encoding specifies the coder, whether frames are adjoined, and write options:

```rex
IM.Encoding {
    format = IM.Format { name = "webp" },
    mode = IM.AdjoinFrames,
    options = [IM.WriteQuality 82, IM.WriteStripMetadata]
}
```

`AdjoinFrames` creates one encoded file. `SeparateFrames` creates a numbered series internally and
returns `MultipleImages`. Rex never constructs or observes the numbered filenames.

## Failures

Expected ImageMagick failures are returned as `Result` errors containing `ImageMagickError`.
Infrastructure failures—such as a missing executable, CAS failure, or tool-executor failure—remain
host evaluation errors. Image comparison status 1 is interpreted semantically as “different,” not
as an execution failure.

## Agent guidance

Prefer the narrowest function that matches the request:

1. Use `transform` for one input.
2. Use `generate` for synthetic content.
3. Use `composite`, `montage`, or `compare` for those specific operations.
4. Use `render` only when sources and sequence operations must be interleaved.
5. Use `Define` only for coder-specific behavior not represented by a regular option.

See [`examples/imagemagick`](examples/imagemagick/README.md) for complete Rex programs. Every
example is parsed and typechecked in the workflow test suite.
Cross-tool pipelines are demonstrated in the
[`examples/imagemagick_ffmpeg`](examples/imagemagick_ffmpeg/README.md) directory.

## Host architecture

ImageMagick compiles into a generic symbolic `ToolExecutionPlan`. Plans contain CAS inputs and
opaque path slots, not host paths. `LocalToolExecutor` materializes a temporary workspace and runs
the command today. The `ToolExecutor` trait is the replacement boundary for isolated sandbox
execution later; no Rex-visible ImageMagick type depends on the local executor.
